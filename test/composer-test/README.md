# HKL Composer Test Suite

A headless-Chromium suite for Composer. Each **fixture** is a named Composer
state — a `setup` snippet run in the page and/or real keystrokes — checked
against the universal invariants plus its own assertions. Every fixture runs
every invariant; the modes below only decide *which* fixtures run.

## Running

Needs the dev proxy (`pnpm dev`, serving `http://localhost:5170/composer/`).

| Command | Runs | When |
|---|---|---|
| `pnpm test:composer:affected` | fixtures that execute the code you changed, ∪ the fast tier | after a scoped change — the default |
| `pnpm test:composer:fast` | the fast tier | a quick broad check |
| `pnpm test:composer` | every fixture | once per change set, before calling it done |
| `node test/composer-test/run.mjs scenario <name> [--keep-open]` | one fixture | debugging |

Options for any mode (`node test/composer-test/run.mjs <mode> …`):

- `--group a,b` — only these categories (`fixtures/<category>.mjs`)
- `--only a,b` — only fixtures whose name starts with a listed prefix
  (fixture names, not `visualBaseline` names)
- `--list` — print the selection (and `affected`'s report) and exit
- `--update-baselines` — accept new visual output
- `--coverage [path]` — record per-fixture coverage (default
  `out/coverage-map.json`)
- `HKL_INDEX_CHECK=1` — also verify every splice against an offscreen full
  render (the page-splice reference gate) and every VoiceIndex against the
  uncached computations; slower, catches what the plain run cannot

Run long gates in the background with output captured to a file
(`… > log 2>&1; echo EXIT=$?`), and quote the runner's own `N/M passed` line.
Nothing else may load the machine meanwhile — no `pnpm build`, no second
Chromium job: a visual fixture shot mid-relayout under a concurrent build has
failed for real, and the composer-inspect probe runner's deadline expires
under a concurrent suite.

After the `N/M passed` line the runner prints two diagnostics: the **splice
ledger** (how many fixtures rendered with and without a full engrave, the
full engraves grouped by reason — the triage list for the splice invariant)
and **where the wall went** (setup time against total, and the eight slowest
fixtures — a slow suite is usually a few fixtures building multi-page scores
one chord at a time).

### `affected`

`out/coverage-map.json` records, per fixture, the source lines it executed
(V8 block coverage mapped back to TypeScript through Vite's sourcemaps) and a
snapshot of every module as measured. `affected` diffs each module against
its snapshot and selects every fixture that executed a touched line; a
touched line at module scope selects every fixture that ran code in that
module; type-only and comment lines select nothing. A fixture whose spec or
assertions differ from `HEAD` is selected too. The report also names:

- **UNTESTED** changed lines — code no fixture executes. Usually a missing
  fixture.
- changed files the map cannot speak for (new modules, CSS, `index.html`) and
  runner changes — choose `--group` or the full suite for those.

The line sets over-approximate (V8 leaves gaps after some expressions), so
the selection errs toward running more. The map goes stale as code moves;
regenerate it after large changes:

```bash
node test/composer-test/run.mjs full --coverage   # rewrites out/coverage-map.json
node test/composer-test/select-fast.mjs           # re-picks the fast tier from it
```

### The fast tier

`fast-tier.json` is generated by `select-fast.mjs` — never hand-edited. It is
the safety net under `affected`, covering what coverage cannot see (non-JS
changes, a stale map, timing-dependent paths such as idle slices, observers
and deferred renders), so it is chosen for breadth: first one fixture per
category, then greedily by new source lines per second until the budget
(`--budget-s`, default 40 s measured) is spent. The script prints the
coverage curve and the modules where the fast tier and the full suite differ
most.

## Invariants

Applied to every fixture by the runner:

- **placeholder** — every layer's placeholders sum to the measure's remaining
  ticks
- **no tie orphans** — every `data-tie-partner` resolves
- **pagination first-fit** — no mounted page overflows, none has room for the
  next page's first system
- **roundtrip** — `serialize → replaceDocument → serialize` is identical
  (placeholder ids normalized)
- **cursor-trace** — consecutive voice-1 cursor positions render at distinct
  rects (> 3 px). Exemptions: `expectedZeroDeltaPairs: [[from, to], …]`;
  `skipCursorTrace: true` for fixtures orthogonal to cursor geometry
- **console** — no error-level message; `allowConsole: [/re/]` for messages a
  fixture provokes on purpose
- **splice** — no full render among the fixture's own edits unless by design:
  `single-line partition`, `all lines …`, or `forced full render (<cause>)`
  (new document, view staves, zoom, page scale, string render). The failure
  detail prints the render sequence; a fixture whose point is a derive
  declares `fullRender: '<why>'`
- **visual** — when the fixture declares `visualBaseline: '<name>'`

plus the fixture's own `ASSERTIONS[name]`: `[{ name, expr }]`, each `expr`
returning `{ ok, detail? }` in the page (use `window.__test.*` helpers).

Output: per-fixture pass/fail; `out/summary.json` (with `visualMeta` — the
capture framing: clip, viewport, the element that set the content box's left
edge — so a framing shift is distinguishable from a rendering change);
`out/<name>.png` for visual fixtures; on a non-visual failure,
`<name>-live.png` + `<name>-reengrave.png` in `$HKL_FAIL_SHOTS` (default
`$TMPDIR/hkl-composer-fail`), the spliced page against a full re-engrave.
Exit code 0 = all pass, 1 = failures, 2 = infrastructure failure.

## Adding a fixture

**Every Composer bug fix lands with a fixture that fails on the broken
version, and every feature with its happy path plus its rejection cases.**

1. Add an entry to `FIXTURES` in the matching `fixtures/<category>.mjs` (new
   category: create the module and import it in `fixtures/index.mjs`).
   `setup` has `m` (model), `c` (cursor), `r` (reRender) and `bridge` in
   scope; `setupKeys` entries are characters or
   `{ key: 'ArrowRight', ctrl: true, shift: true, alt: true }`.
2. Add `ASSERTIONS[name]` if the universal invariants don't cover the
   behavior. Assertion and setup bodies are untagged template literals
   injected as strings: every backslash is consumed by the template — see
   lessons.md before writing a regex or a backtick in one.
3. For pixels, add `visualBaseline: '<name>'`; the first run seeds
   `baselines/<name>.png`. Framing is a compact content crop; page-level
   layout fixtures add `visualFullPage: true` (later pages must be mounted by
   the setup). Scenario runs perform the visual check too, so one fixture can
   be verified or re-seeded in about a second.
4. Run it against the current code first — it must fail for the reason the
   fix addresses — then implement.

Prefer existing assertions to new ones, and one fixture per behavior surface:
the grid of fixtures × universal invariants is the coverage.

## Reviewing a visual failure

**Produce a heatmap, never a side-by-side** (Max, 2026-09-03), and open it
before quoting numbers:

```bash
python3 test/composer-test/heatmap.py baselines/<name>.png out/<name>.png \
  /tmp/<name>.png --label "baseline vs output — <name>"
```

Below a max channel delta of 20 the tool marks pixels binary (yellow in a red
halo), since an amplified one-level anti-aliasing flip is invisible. Three
traps, all hit for real:

- **Diff the right pair.** Baseline-vs-output only says the rendering
  changed. The *defect* question is self-consistency: the spliced page
  against a full re-engrave of the same document (the failure shots above).
  Say which pair a heatmap shows.
- **Verify the framing.** State the page, scroll position and system count
  the capture contains.
- **Prove the capture is fresh.** Check the runner's fixture count and the
  `out/` mtimes before diffing.

Never re-seed to make a red gate green; `--update-baselines` is for a change
whose reason is known.

## State reset between fixtures

`RESET_SNIPPET` (`lib/runner-core.mjs`) clears what lives outside the model:
open dialogs, input state (mode, cursor mode, pending hairpin/tuplet/slur,
layer cursor), held keys (via `__bridgeMock.sendHeldKeys([])`), scroll
position, view mode + theme + zoom (page view, light, 100 %, and their
persisted keys) and the HEJI flag (pinned off for the shared document;
`heji_default_on` probes a fresh instance). **Any new module-private or
global Composer state must be cleared there** — leaks produce order-dependent
failures, and `affected`/`--group` runs reorder fixtures (lessons.md "State
machines outside the model leak across automated tests").

## Verifying against the unfixed build

`run-unfixed.sh <fixture…>` stashes `apps/composer/src`, runs the fixtures in
scenario mode under `HKL_INDEX_CHECK`, and restores. "Unfixed" means HEAD; a
fixture pinning a fix that is only wrong on top of an uncommitted feature
passes there legitimately. Nothing else may use the dev server while it runs.
Never override `TMPDIR` for `run.mjs` or `run-unfixed.sh` — Chromium's debug
endpoint never comes up under a deep `TMPDIR` and every fixture reports an
infrastructure failure.

## Debugging

`run.mjs scenario <name> --keep-open` leaves Chromium running for DevTools.
In the page: `window.__hkl_composer` (`bridge, model, renderer, cursor,
reRender`), `window.__test.*` (assertion helpers, `runRoundTrip`),
`window.__bridgeMock` (`sendHeldKeys`, `captured`, `drain`, `reset`),
`window.__cursorTrace(voice, exemptions)`, `window.__waitForScrollSettle(ms)`.

When a test's pixels disagree with live behavior on the same code, list every
command the runner issues that a live session does not (mock injects,
cursor-trace, forced view mode, RAF waits) before hypothesizing (lessons.md
"Test/live divergence: diff the flows before hypothesizing").

## Self-tests

When changing the runner, check that deliberate regressions are caught:

- CURSOR: revert the past-end conditional (`cc2f76b`) → `pastEnd_fullLast`
- ROUNDTRIP: break `setAttributeNS` for `xml:id` → Verovio "Unable to match
  @tie" console errors
- INPUT: change a keybinding in `input.ts` → `kbd_durationDigits` /
  `kbd_ctrlNavBarJump`
- TIE: restore the asymmetric `data-tie-partner` in `insertWithSplit` →
  `m1TieDeleteMiddleFromSplit`
- VISUAL: rename a baseline PNG → the diff is written to `out/`

## Known gaps

- `visual.mjs` compares PNG bytes (hash fallback); `pixelmatch` would
  tolerate sub-pixel anti-aliasing.
- The bridge mock attaches after page load, so boot-time `composer-hello` /
  `request-state` are only tested via an explicit `bridge.send()`.
- If the runner's parent shell dies mid-run, Chromium and its
  `$TMPDIR/hkl-composer-test-*` profile leak (`stop()` runs only from
  `main()`'s `finally`); kill that PID only — never by name pattern
  (lessons.md "Headless Chromium leaks on parent-shell kill").
